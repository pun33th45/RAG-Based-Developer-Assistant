# Contribution Plan

This plan keeps GitHub activity real and recruiter-friendly. Do not backdate commits or create empty changes. Each update should improve the project, documentation, tests, or learning notes.

## Five-Day Plan

| Day | Focus | Example Commit |
| --- | --- | --- |
| Day 1 | Refactor backend and improve runtime validation | `feat: add runtime validation and API logging` |
| Day 2 | Add backend API tests | `test: add upload API tests` |
| Day 3 | Improve documentation | `docs: add API and architecture guides` |
| Day 4 | Add a small product feature | `feat: add index reset endpoint` |
| Day 5 | Fix bugs and improve errors | `fix: sanitize provider errors` |

## Weekly Habits

- Open one issue before starting any medium-sized change.
- Keep commits focused on one logical improvement.
- Write tests for backend behavior before expanding the UI.
- Update README screenshots after visible UI changes.
- Use pull requests for larger changes, even in personal repos, to show review discipline.

## Good Commit Message Examples

- `feat: add API validation`
- `fix: handle empty uploads`
- `docs: update architecture guide`
- `test: add query endpoint coverage`
